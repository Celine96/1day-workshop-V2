# 2.1 API란? — "약속·창구·출입증"

---

> **이 세션의 목표:** 비개발자가 "API"라는 단어를 처음 들어도, 클로드 코드가 데이터를 가져와서 멋진 HTML 대시보드를 만들어주는 걸 직접 경험하는 시간이에요. 끝나면 태이님 폴더에 직접 만든 KPI 대시보드 HTML 한 장이 남아 있을 거예요.

---

### [개념] 비유로 한 번에 잡기

실무에서 데이터를 자동으로 다루다 보면 "API"라는 단어를 자주 만나요. 어렵게 들리지만, 핵심만 풀어보면 이거예요.

| 개념 | 비유 | 실제 의미 |
|---|---|---|
| **API** | 인스타 사장님이 정해놓은 *창구* | 외부 서비스(인스타·국토부·구글 등)가 우리에게 데이터를 주고받기 위해 정해 놓은 **약속된 통로**예요. 사장님께 매일 직접 가서 받아 적는 게 아니라, 사장님이 만든 창구로 요청하면 정해진 형식으로 데이터를 보내줘요. |
| **API 키** | 창구를 쓰기 위한 *출입증* | 아무나 데이터를 빼갈 수 없도록, 등록한 사람에게만 발급되는 **개인 식별자**예요. 비밀번호처럼 취급해요(다른 사람에게 절대 공유 X). |
| **API 호출** | 창구에 *요청서를 내미는 것* | "2026-04-21 도달 데이터 주세요"처럼, 정해진 형식의 요청을 보내면 **JSON**이라는 깔끔한 표 형태로 답이 와요. |

---

### 오늘 만날 API 예시

- **Instagram Insights API** — 인스타가 정해놓은 창구. 도달·DM·팔로워 같은 숫자를 받을 수 있어요. (오늘 KAI가 쓰는 API)
- **국토부 실거래가 API** — 국토교통부가 정해놓은 창구. 거래된 부동산 정보를 받을 수 있어요.
- **Google Calendar API** — 구글이 정해놓은 창구. 일정 데이터를 받거나 만들 수 있어요.

> 오늘 워크숍에서 코드를 직접 짜진 않아요. "API라는 통로가 있다 → 그 통로로 받은 데이터를 클로드 코드가 분석한다" 흐름만 잡으시면 충분해요.
