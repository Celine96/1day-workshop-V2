# 3.2 PRD (제품 요구사항 문서)

---

### [개념] PRD(Product Requirements Document)란?

3.1에서 에이전트의 개념을 배웠습니다. 그런데 한 가지 빠진 것이 있습니다. 에이전트에게 "무엇을 해야 하는지"를 어떻게 정확하게 전달할 것인가? 라는 문제입니다.

AI에게 "알아서 KPI 레포트 만들어줘"라고 하면 어떻게 될까요? 어떤 데이터 기간을 쓸지, 어떤 KPI 목표를 기준으로 할지, 어떤 디자인으로 만들지, 어떤 기준으로 품질을 판단할지 모두 AI가 임의로 결정하게 됩니다. 결과물이 매번 달라지고, 원하는 품질을 안정적으로 얻기 어렵습니다.

이 문제를 해결하는 것이 바로 PRD(Product Requirements Document)입니다. PRD는 AI 에이전트에게 주는 상세 업무 지시서로, 다음과 같은 핵심 항목들을 담고 있습니다:

| 항목 | 역할 | 예시 (KAI 시스템) |
|------|------|------|
| 목적 | 이 시스템이 왜 필요한지 | "마케팅 KPI를 자동 추적하여 의사결정 사이클을 단축한다" |
| 목표 지표 | 성공을 어떻게 측정할지 | "월간 신규 적격 관심 유저 수, 주간 도달 ≥500, 참여율 ≥5%" |
| 에이전트 구성 | 누가 어떤 역할을 맡는지 | "기획자(Max), 분석가(KAI), 검수자(Luna)로 분리" |
| 파이프라인 | 작업이 어떤 순서로 흐르는지 | "데이터 수집 → 가공 → 시각화 → 검수 → 발행" |
| 입출력 정의 | 무엇을 넣고 무엇이 나오는지 | "IG Insights API + KPI 목표값 → 단일 HTML 대시보드" |
| 품질 기준 | 어떤 기준을 지켜야 하는지 | "숫자 정합성, 면책 문구 필수, 모바일 호환" |

PRD가 잘 작성되어 있으면, AI 에이전트는 매번 일관된 품질의 결과물을 만들어낼 수 있습니다.

### [개념] REXA 마케팅 에이전트 PRD 살펴보기 — 2부에서 체험한 작업의 뒷면

2부에서 직접 체험한 'KAI의 KPI 대시보드 파이프라인' 기억하시나요? IG 일별 데이터를 넣으면 HTML 레포트가 나오는 그 작업입니다.

그 작업이 안정적으로 돌아가려면 뒤에서 PRD가 모든 것을 정의하고 있어야 합니다. REXA 마케팅 에이전트 PRD v2.0의 핵심 구조를 살펴볼게요.

| 항목 | 내용 |
|------|------|
| 1. 개요 | 목적: REXA 사전 마케팅 & 초기 유저 확보 / 핵심 가치: 마케팅 전담 인력 없이 AI 에이전트로 자동화 |
| 2. 전략 및 목표 | North Star Metric: 월간 신규 적격 관심 유저 수 / Input Metrics (Phase 1 IG): 주간 도달 500, 참여율 5%, 수신 DM 2건/주, HOT DM 1건/주 |
| 3. 에이전트 팀 | Max(매니저): 일일·주간 계획, KPI 추적 / KAI(Growth Analyst): 데이터 수집·분석·레포트 / Luna(검수): 품질 게이트, 법률 준수 |
| 4. 파이프라인 | 데이터 수집 → 가공 → 시각화 → 검수 → 발행 |
| 5. 품질 기준 | 숫자 정합성, 면책 문구, KPI 목표 대비 ✅/❌ 표시 일관성, 차트 가독성 |

PRD 안에 에이전트별 상세 스펙도 포함할 수 있습니다. 예를 들어 REXA PRD에서는 각 에이전트의 사용 도구, 입출력, 판단 기준까지 정의하고 있습니다.

- KAI (Growth Analyst): IG Insights API 데이터를 입력받아 KPI 대시보드 HTML과 위험 신호 알림을 생성합니다. 숫자 정합성, 면책 문구 포함, 두 계정 합산 일관성을 품질 기준으로 따릅니다.
- Luna (검수): KAI의 결과물을 입력받아 승인 또는 반려를 판정합니다. 80점 이상이면 자동 승인, 50~79점이면 사람 검토, 50점 미만이면 반려합니다.

### Claude Code에게 PRD를 요청하는 방법

PRD를 처음부터 직접 작성할 필요는 없어요. 클로드 코드에게 목적과 현재 상황을 간단히 설명하면, AI-Native 방식으로 함께 작성할 수 있습니다.

[클로드 코드에 입력]
```
"나는 [자동화하고 싶은 업무]를 하고 있어.
현재는 [현재 작업 방식]으로 진행하고 있는데,
이걸 자동화하기 위한 PRD를 작성해줘."
```

> 구체적인 PRD 작성 실습은 3.4에서 직접 진행할 예정이에요. 위 예시와 REXA의 PRD를 참고하면서 함께 만들어 볼게요.

### PRD와 CLAUDE.md의 관계

작성한 PRD를 `CLAUDE.md` 파일로 저장하면, 클로드 코드가 매 세션마다 자동으로 읽습니다. 즉, PRD를 CLAUDE.md에 담아두면 매번 다시 설명할 필요 없이 클로드가 프로젝트 맥락을 기억한 상태로 작업을 시작합니다.

> CLAUDE.md 활용법에 대한 자세한 내용은 [3.5 실무 팁](/part3/3-5-tips#claude-md-활용법)을 참고해 주세요.
